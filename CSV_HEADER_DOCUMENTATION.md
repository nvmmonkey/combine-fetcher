## Section 1: Market Identity (Columns 1-2)

### Column 1: `timestamp`
**Type:** String (ISO 8601 format)
**Format:** `YYYY-MM-DDTHH:MM:SS.sss`
**Example:** `2026-01-26T11:23:13.549`

The exact UTC timestamp when this record was captured, with millisecond precision.

**Usage:**
```python
# Python parsing
from datetime import datetime
ts = datetime.fromisoformat("2026-01-26T11:23:13.549")
```

---

### Column 2: `market_slug`
**Type:** String
**Format:** `btc-updown-15m-{window_start_timestamp}`
**Example:** `btc-updown-15m-1769426100`

Unique identifier for the 15-minute BTC up/down market window.

**Structure:**
- `btc-updown-15m`: Market type (Bitcoin price direction, 15-minute expiry)
- `{window_start_timestamp}`: Unix timestamp when the 15-minute window begins

**Window Logic:**
- Window duration: 900 seconds (15 minutes)
- Windows align to :00, :15, :30, :45 minute marks
- A market at `1769426100` starts at 2026-01-26 11:15:00 UTC and ends at 11:30:00 UTC

## Section 2: Binance Data (Columns 3-4, 28-30)

### Column 3: `binance_price`
**Type:** Float (USD, 2 decimal places)
**Range:** Typically 80,000 - 100,000 for BTC (as of 2026)
**Example:** `87952.04`

The current BTC/USDT spot price from Binance. This is the mid-price derived from the order book or last traded price.

**Important:** This is the UNDERLYING asset price for the binary options.

---

### Column 4: `binance_volume`
**Type:** Float (BTC units, 2 decimal places)
**Range:** 0 to millions
**Example:** `131252.33`

**IMPORTANT:** Despite the name, this is actually the **1-minute rolling volume**, NOT cumulative volume.

- Represents total BTC traded in the last 60 seconds
- Updates continuously via Binance `@aggTrade` WebSocket stream
- Used to detect trading activity bursts

---

### Column 28: `binance_bid` (NEW)
**Type:** Float (USD, 2 decimal places)
**Example:** `87952.03`

The best BID price on Binance order book (highest price buyers are willing to pay).

**Formula:** `best_bid = max(all bid prices)`

---

### Column 29: `binance_ask` (NEW)
**Type:** Float (USD, 2 decimal places)
**Example:** `87952.04`

The best ASK price on Binance order book (lowest price sellers are willing to accept).

**Formula:** `best_ask = min(all ask prices)`

---

### Column 30: `binance_spread_bps` (NEW)
**Type:** Float (basis points, 4 decimal places)
**Range:** 0 to ~10 for liquid assets
**Example:** `0.0011`

The bid-ask spread expressed in basis points (1/100th of a percent).

**Formula:**
```
binance_spread_bps = ((ask - bid) / mid_price) × 10000
where mid_price = (bid + ask) / 2
```

**Interpretation:**
- `< 1 bps`: Extremely tight spread (high liquidity)
- `1-5 bps`: Normal for BTC
- `> 10 bps`: Wide spread (low liquidity or high volatility)

## Section 3: Polymarket YES Token (Columns 5-8)

### Column 5: `yes_bid`
**Type:** Float (price, 4 decimal places)
**Range:** 0.0000 - 1.0000

The highest price buyers are willing to pay for the YES token.

- Sum of `yes_bid` + `no_bid` is typically < 1.00 (the spread is bookmaker profit)

The number of YES tokens available at the best bid price.

### Column 7: `yes_ask`
**Type:** Float (price, 4 decimal places)
**Range:** 0.0000 - 1.0000
**Example:** `0.2700`

The lowest price sellers are willing to accept for the YES token.

---

### Column 8: `yes_ask_size`
**Type:** Float (token count, 0 decimal places)
**Range:** 0 to millions
**Example:** `2490`

The number of YES tokens available at the best ask price.

---

### Column 42: `yes_spread_bps` (NEW)
**Type:** Float (basis points, 4 decimal places)
**Range:** 0 - 100,000+
**Example:** `377.3585`

The YES token bid-ask spread in basis points.

**Formula:**

**Interpretation:**

## Section 5: Timing (Columns 13-14, 23-27)

### Column 13: `time_to_open`
**Type:** Integer (seconds)
**Range:** Negative values expected during active trading
**Example:** `-493`

**IMPORTANT SEMANTICS:**

| Value | Meaning | Trading State |
|-------|---------|---------------|
| `> 0` | Market opens in X seconds | PRE-MARKET (no trading yet) |
| `= 0` | Market is opening NOW | MARKET OPEN |
| `< 0` | Market opened X seconds ago | **ACTIVE TRADING** |

**Formula:** `time_to_open = window_start_timestamp - current_timestamp`

**Your example `-493` means:** The market opened 493 seconds (8.2 minutes) ago and is actively trading.

---

### Column 14: `time_to_expiry_minutes`
**Type:** Float (minutes, 2 decimal places)
**Range:** 0 to 15
**Example:** `6.78`

Time remaining until the market resolves and the option expires.

**Formula:**
```
time_to_expiry_minutes = (window_end_timestamp - current_timestamp) / 60
```

**When this reaches 0:** The market resolves and `market_resolved = true`.

---

### Column 23: `timestamp_unix_ms` (NEW)
**Type:** Integer (milliseconds since Unix epoch)
**Example:** `1769426593549`

Unix timestamp in milliseconds for programmatic parsing.

**Conversion:**
```python
import datetime
dt = datetime.datetime.fromtimestamp(1769426593549 / 1000, tz=datetime.timezone.utc)
# Result: 2026-01-26 11:23:13.549 UTC
```

### Column 24: `binance_update_ms` (NEW)
**Type:** Integer (milliseconds since Unix epoch)
**Example:** `1769426593549`

Timestamp of the last Binance price update. Used for freshness checking.

---

### Column 25: `poly_yes_update_ms` (NEW)
**Type:** Integer (milliseconds since Unix epoch)
**Example:** `1769426593412`

Timestamp of the last YES token price update from Polymarket.

---

### Column 26: `poly_no_update_ms` (NEW)
**Type:** Integer (milliseconds since Unix epoch)
**Example:** `1769426593412`

Timestamp of the last NO token price update from Polymarket.

---

### Column 27: `latency_binance_poly_ms` (NEW)
**Type:** Integer (milliseconds)
**Range:** Can be negative
**Example:** `137`, `-50`

**Differential latency:** `binance_update_ms - average(polymarket_update_times)`

**Interpretation:**
- **Positive (137):** Binance data is 137ms NEWER than Polymarket
- **Negative (-50):** Polymarket data is 50ms NEWER than Binance
- Near 0: Both data sources are synchronized

## Section 6: Option Parameters (Columns 15-16)

### Column 15: `strike_price`
**Type:** Float (USD, 2 decimal places)
**Range:** Typically close to current BTC price
**Example:** `87952.04`

The reference price that determines if YES or NO wins:
- If `final_btc_price >= strike_price` → YES wins, pays $1
- If `final_btc_price < strike_price` → NO wins, pays $1

**Source:**
1. Initially: Uses current `binance_price` as placeholder
2. After ~30 seconds: Fetched from Polymarket API (Gamma API)
3. Final: The actual strike price for the binary option

**Note:** In early records, you may see `strike_price = binance_price` (placeholder before fetch completes).

---

### Column 16: `realized_volatility`
**Type:** Float (annualized, 6 decimal places)
**Range:** 0.05 to 3.0 (clamped)
**Example:** `0.031465` (3.15% annual volatility)

**IMPORTANT:** This is the BLENDED volatility from the Fibonacci multi-timeframe calculator.

**Calculation:**
```
realized_volatility = weighted_average(vol_1sec, vol_5sec, vol_13sec, vol_34sec, vol_89sec)
                    = (1×vol_1sec + 2×vol_5sec + 3×vol_13sec + 5×vol_34sec + 8×vol_89sec) / 19
```

**Weights follow Fibonacci sequence:** 1, 2, 3, 5, 8 (sum = 19)

**Source priority:**
1. `BOOTSTRAP` - Historical Binance k-line data (first ~16 hours)
2. `REALTIME` - Live WebSocket data accumulation
3. `1MIN_FALLBACK` - Fallback to 1-minute aggregated data

## Section 7: Greeks (Columns 17-20)

### Column 17: `delta_yes`
**Type:** Float (dimensionless, 8 decimal places)
**Range:** 0.0 to 1.0 (clamped)
**Example:** `0.04012795`

**Delta for the YES call option:** Sensitivity of option price to changes in underlying BTC price.

**Formula (simplified):**
```
delta ≈ probability of YES winning × option payoff sensitivity
```

**Interpretation:**
- `0.04`: YES option price changes by ~4% of BTC price change
- `delta → 1.0`: Deep ITM (BTC price well above strike)
- `delta → 0.0`: Deep OTM (BTC price well below strike)
- `delta ≈ 0.5`: At-the-money

**For binary options:** Delta represents the risk-neutral probability of the option expiring in-the-money.

---

### Column 18: `gamma`
**Type:** Float (dimensionless, 8 decimal places)
**Range:** -1e6 to 1e6 (clamped), typically -0.001 to 0.001
**Example:** `0.00000023` or `-0.00000007`

**Gamma:** Rate of change of delta with respect to underlying price. Second derivative of option price.

**CRITICAL - Can Be Negative:**

| Condition | Gamma | Explanation |
|-----------|-------|-------------|
| `spot < strike` | **Negative** | Delta decreasing as price moves away from strike |
| `spot ≈ strike` | Near zero | At-the-money, transition point |
| `spot > strike` | Positive | Delta increasing as price moves toward strike |

**Why negative?** For binary options, gamma is negative OTM because delta flattens (approaches 0) as price moves away from the strike.

**Formula:**
```rust
let d1 = (ln(spot/strike) + (vol²/2)×t) / (vol×√t)
gamma = (n'(d2) × d1) / (spot² × vol² × t)
```

---

### Column 19: `vega`
**Type:** Float (USD per 1% vol change, 8 decimal places)
**Range:** -1e6 to 1e6 (clamped)
**Example:** `0.00001433`

**Vega:** Sensitivity of option price to changes in volatility.

**Interpretation:**
- `0.00001433`: Option price increases by $0.00001433 for each 1% increase in volatility
- Binary options have LOW vega (mostly determined by probability, not volatility)
- Maximum vega occurs at-the-money with longer time to expiry

---

### Column 20: `theta`
**Type:** Float (USD per day, 8 decimal places)
**Range:** Typically negative (time decay), -1e6 to 1e6 (clamped)
**Example:** `-420.98` or `-1339.06`

**Theta:** Sensitivity of option price to passage of time (time decay).

**Interpretation:**
- **Negative values (-420.98):** Option loses $420.98 per day due to time decay
- Large negative values indicate significant time value erosion
- Binary options experience accelerating time decay near expiry

**Why very negative?** As expiry approaches, uncertainty resolves quickly, causing rapid option value changes.

## Section 9: Multi-Timeframe Volatility (Columns 31-36)

### Columns 31-35: `vol_1sec`, `vol_5sec`, `vol_13sec`, `vol_34sec`, `vol_89sec` (NEW)
**Type:** Float (annualized, 6 decimal places)
**Range:** 0.05 to 3.0 (clamped)
**Example:** `0.117953`, `0.052750`, `0.033915`, `0.020971`, `0.020971`

Realized volatility calculated over different time windows following Fibonacci sequence.

**Time windows (Fibonacci):** 1s, 5s, 13s, 34s, 89s

**Calculation method:** Welford's online algorithm for numerical stability

**Interpretation:**
- `vol_1sec = 0.117953` (11.8%): Very short-term volatility (noise)
- `vol_89sec = 0.020971` (2.1%): Longer-term baseline volatility
- `vol_1sec > vol_89sec`: Current spike vs baseline

**Usage:** These individual values feed into the blended `realized_volatility` (Column 16).

---

### Column 36: `volatility_regime` (NEW)
**Type:** String (enum)
**Values:** `"BOOTSTRAP"`, `"LOW"`, `"NORMAL"`, `"HIGH"`, `"EXTREME"`
**Example:** `"EXTREME"`

Classification of current market volatility state.

**Regime thresholds:**
```
regime = if bootstrapping: "BOOTSTRAP"
else if vol_89sec < 0.15: "LOW"
else if vol_89sec < 0.30: "NORMAL"
else if vol_89sec < 0.60: "HIGH"
else: "EXTREME"
```

**Your example `"EXTREME"`:** vol_89sec is likely > 0.60 (60% annual volatility), indicating very turbulent market conditions.

## Section 12: Greeks Formula Reference

For AI models using this data for option pricing or trading strategies:

### Black-Scholes for Binary/Cash-or-Nothing Options

The Greeks are calculated using modified Black-Scholes formulas for binary options:

```rust
// Time in years
t = time_to_expiry_minutes / 525600  // Minutes per year

// d1 and d2 calculations
d1 = (ln(spot/strike) + (vol²/2)×t) / (vol×√t)
d2 = (ln(spot/strike) - (vol²/2)×t) / (vol×√t)

// Normal PDF
n'(x) = exp(-x²/2) / √(2π)

// Greeks
delta = n'(d2) / (spot × vol × √t)          [clamped 0 to 1]
gamma = n'(d2) × d1 / (spot² × vol² × t)    [can be negative!]
vega = n'(d2) × √t × 0.01                   [per 1% vol change]
theta = -(spot × n'(d2) × vol) / (2×√t) / 365  [per day]
```

## Usage Examples for AI/ML Models

### Python: Load and Parse

```python
import pandas as pd
import numpy as np
from datetime import datetime

# Load CSV
df = pd.read_csv('multi_market_data.csv')

# Convert timestamp
df['datetime'] = pd.to_datetime(df['timestamp'])

# Filter for active trading only
active = df[df['time_to_open'] < 0]  # Only records after market open

# Calculate mid prices
df['yes_mid'] = (df['yes_bid'] + df['yes_ask']) / 2
df['no_mid'] = (df['no_bid'] + df['no_ask']) / 2

# Calculate implied probability from prices
df['yes_implied_prob'] = df['yes_mid']
df['no_implied_prob'] = df['no_mid']

# Identify high-volatility periods
high_vol = df[df['volatility_regime'] == 'EXTREME']
```

### Feature Engineering for Trading Signals

```python
# Price momentum
df['btc_return_1m'] = df['binance_price'].pct_change(60)  # 60-second return

# Volatility term structure
df['vol_term_structure'] = df['vol_1sec'] - df['vol_89sec']
# Positive = short-term vol spike, Negative = vol mean-reverting

# Polymarket inefficiency
df['arb_opportunity'] = df['yes_mid'] + df['no_mid'] - 1.0
# Negative = arbitrage opportunity (sum < 1)

# Latency impact
df['data_freshness'] = df['timestamp_unix_ms'] - df[['binance_update_ms', 'poly_yes_update_ms', 'poly_no_update_ms']].max(axis=1)
```

### Common Pitfalls to Avoid

1. **Misinterpreting `time_to_open`:**
   - ❌ Wrong: "Positive means market is about to open"
   - ✅ Correct: "Negative means market IS OPEN (seconds since open)"

2. **Using `binance_volume` as cumulative:**
   - ❌ Wrong: "Total volume since market start"
   - ✅ Correct: "Rolling 1-minute window volume"

3. **Assuming gamma is always positive:**
   - ❌ Wrong: "Gamma > 0 always"
   - ✅ Correct: "Binary options have negative gamma when spot < strike"

4. **Ignoring `strike_price` placeholder:**
   - ⚠️ Early records may show `strike_price = binance_price`
   - ✅ Check for strike price updates after ~30 seconds

## Glossary

| Term | Definition |
|-------|------------|
| **ATM** | At-The-Money: spot price ≈ strike price |
| **ITM** | In-The-Money: spot > strike for YES call |
| **OTM** | Out-Of-The-Money: spot < strike for YES call |
| **BPS** | Basis Points: 1/100th of 1% (0.0001) |
| **Clamped** | Value restricted to specified range |
| **Annualized** | Per-year rate (volatility is always quoted annualized) |
| **Mid-price** | Average of bid and ask: (bid + ask) / 2 |
| **Spread** | Difference between best bid and best ask |

**File Encoding:** UTF-8
**Line Ending:** LF (Unix)
**Delimiter:** Comma (`,`)
**Quote Character:** None (numeric fields unquoted)
**Header Row:** Present (first row)

**Null/Empty Values:**
- Boolean fields: `false` or `true`
- String fields: Empty string `""` (not `null`)
- Numeric fields: `0` or calculated placeholder
